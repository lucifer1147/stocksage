# The Backend

Now this is the fun part. I designed it in [__Django__](https://www.djangoproject.com/). 

## Setting up the basics
For the starters, [create a virtual enviroment](https://docs.python.org/3/library/venv.html), and activate it. It is highly recommended that you do so, so that it doesn't clutter the your main installation

Then just run `pip install -r requirements.txt`. What it will do is install the modules' specific versions as specified in the `requirements.txt` file.

It will take time as some noteably large modules will be installed which include (but are not limited to):
- Django itself
- PyTorch (for the :sparkles: __AI Integration__ :sparkles:)
- Sklearn (just for the `Roubust Scaler`)
- Numpy, Pandas, Matplotlib (you know the use)
- etc...

If you want to host the backend locally, first make migrations using `py manage.py makemigrations`, then apply the migrations using `py manage.py migrate` (these are two very important steps), then finally host the server locally using `py manage.py runserver`.\
All of this goes without saying that you should be in the directory of your manage.py file. Details on how all of this is hosted can be found on the [__Django Docs__](https://docs.djangoproject.com/en/5.1/)

# The Project Itself
You may notice the lack of visuals on the backend side of things and that's because it is meant for making api calls only. "API calls for what?" you may ask , the answer for that is... idk how to explain it. But you will understand as you read more.

If you noticed, there is a `main.py` sitting right along with the `manage.py`. It is not generated by Django as I made it as an alternative CLI interface for the Project. (The project here being the :sparkles: __AI Integration__ :sparkles:).

## Main.py
It is the actual CLI and can be interacted with as follows:

```
usage: main.py [-h] {train,test,predict} ...

Stock Predictor CLI.

positional arguments:
  {train,test,predict}

options:
  -h, --help            show this help message and exit
  
```
(The test, predict functionalities are yet to be added.)

### train

As the name suggests, it allows you to train a model, namely an [LSTM Model](https://en.wikipedia.org/wiki/Long_short-term_memory) which is implemented in the `.\main\ProjectFiles\neuralnet.py`.

It calls upon the train function whihch iteself is implemented in the `.\main\ProjectFiles\train.py`. It is a _very length and messy_ function and I am still working on making the code comments and prettifying it. It can be accessed and interacted with from the command line as follows:

# ProjectFiles

It is the directory inside the `.\main\` DjangoApp. It contains the main files for the :sparkles: __AI Integration__ :sparkles:.
It contains the following files:
- `train.py`
- `predict.py`
- `indicators.py`
- `utils.py`
- `neuralnet.py`

The `train.py` will also create a sub-directory `Models`. It will contain the files for the models you train (if you choose to save them) in a sub directory by name that you specify in the `saveModelAs` parameter as `<saveModelAs>_files`. For further details, look at the `README.md` file of the `ProjectFiles` directory.
